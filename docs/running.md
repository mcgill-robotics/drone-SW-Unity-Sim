# Running the sim

Start Unity first, then PX4. QGroundControl, ROS 2 and test scripts are optional and can join
at any time.

## Unity

Unity 6.6 (6000.6.0f1), HDRP. Open the project, open a scene from `Assets/_Project/Scenes/`, press
Play. The overlay in the top left says `PX4 SITL: waiting on TCP 4560` until PX4 connects.

| Scene | Vehicle | `PX4_SIM_MODEL` |
|---|---|---|
| `FlightX500.unity` | PX4's X500 quad, numbers from its Gazebo model | `none_iris` |
| `Flight.unity` | Quadplane: 6.5 kg, 16 inch props, placeholder aerodynamics | `gazebo-classic_standard_vtol` |

The scenes are generated by `Assets/Editor/DroneSim/SceneBuilder.cs` (menu: Drone Sim > Build
Flight Scenes). To change a vehicle, edit the builder and rebuild, so the change shows up in a
readable diff.

Run In Background is on, so the sim keeps stepping while another window has focus.

### Tests

Window > General > Test Runner > EditMode > Run All. From a terminal, with the editor closed:

```bash
/Applications/Unity/Hub/Editor/6000.6.0f1/Unity.app/Contents/MacOS/Unity -batchmode -nographics \
  -projectPath . -runTests -testPlatform EditMode -testResults results.xml -logFile test.log
```

## PX4 SITL

Build once. Use the same PX4 release as the flight controller (v1.17.0):

```bash
git clone --recursive -b v1.17.0 https://github.com/PX4/PX4-Autopilot.git
cd PX4-Autopilot
make px4_sitl
```

On macOS you need Xcode's command line tools, `cmake` and `ninja` from Homebrew, and PX4's
Python requirements in a venv. If Homebrew's protobuf is installed, the build fails on C++17 in
Gazebo code we don't use; turn it off:

```bash
python3 -m venv .venv && .venv/bin/pip install -r Tools/setup/requirements.txt
source .venv/bin/activate
ulimit -S -n 2048
make px4_sitl CMAKE_ARGS="-DCMAKE_DISABLE_FIND_PACKAGE_Protobuf=TRUE"
```

Run it from the PX4-Autopilot directory, matching the scene:

```bash
PX4_SIM_MODEL=none_iris ./build/px4_sitl_default/bin/px4 -d                     # FlightX500.unity
PX4_SIM_MODEL=gazebo-classic_standard_vtol ./build/px4_sitl_default/bin/px4 -d   # Flight.unity
```

`-d` runs without PX4's interactive shell; drop it to get the `pxh>` prompt. Running the binary
directly starts no simulator of its own: both airframes start `simulator_mavlink`, which dials
Unity on TCP 4560. (`make px4_sitl gazebo-classic_standard_vtol` would also launch Gazebo, so
don't use it.) The `gz_*` airframes can't be used, because they talk to Gazebo over Gazebo's
own transport instead of MAVLink.

If Unity runs on another machine, set `PX4_SIM_HOSTNAME=<unity host>` for PX4.

### Home location

PX4 takes its home from the GPS that Unity sends, so `PX4_HOME_LAT`, `PX4_HOME_LON` and
`PX4_HOME_ALT` have to be set for Unity, not PX4: export them and launch the editor from the
same terminal (an app started from the Dock doesn't see them), or set them on the `GeoOrigin`
component under `Managers`. The default is
PX4's stock SITL home (47.397742, 8.545594, 488 m). The simulated magnetic field follows home
automatically, from the same table PX4 checks its compass against.

## Flight test

With Unity playing and PX4 connected:

```bash
pip install pymavlink
python3 tools/px4_flight_test.py hover     # take off to 5 m, hover, land
python3 tools/px4_flight_test.py vtol      # quadplane: to 40 m, transition, 60 s on the wing, back, land
```

It prints PX4's estimate once a second, then `PASS`. A non-zero exit says which step failed;
see `--help`.

## QGroundControl

QGC connects by itself: PX4 SITL sends to UDP 14550 on localhost, where QGC listens. The test
script uses 14540, so both can be connected at once. For QGC on another machine, set the PX4
parameter `MAV_0_BROADCAST` to 1, or add a UDP link in QGC.

`missions/vtol_flyaround.plan` is a demo mission for `Flight.unity` at the default home: VTOL
takeoff to 50 m, a lap of about 1.2 km on the wing, VTOL landing at home. In QGC: Plan view >
File > Open, Upload, then Start Mission in the Fly view.

Flight logs (`.ulg`) are written to `PX4-Autopilot/build/px4_sitl_default/rootfs/log/`.

## ROS 2

Two separate connections:

- **PX4 topics** (`/fmu/...`), for code that commands PX4, go through the Micro XRCE-DDS agent.
  Use agent v2.4.x; v3 doesn't talk to PX4 v1.17's client.
  ```bash
  MicroXRCEAgent udp4 -p 8888
  ```
- **Sim topics** (cameras, IMU, ground truth, `/clock`) come from Unity through the ROS TCP
  endpoint. Unity connects to 127.0.0.1:10000; change it on the `ROSConnection` component under
  `Managers` if the endpoint runs elsewhere (Docker, another machine).
  ```bash
  ros2 run ros_tcp_endpoint default_server_endpoint --ros-args -p ROS_IP:=0.0.0.0
  ```

Nothing in the sim depends on ROS. Without an endpoint, Unity logs one connection error and
carries on.

On macOS, run Unity and PX4 natively and ROS 2 in a Linux container, with UDP 8888 and TCP
10000 reachable.

| Topic from Unity | Type | Rate |
|---|---|---|
| `/clock` | rosgraph_msgs/Clock | 10 Hz |
| `/sim/imu/data` | sensor_msgs/Imu | 10 Hz |
| `/sim/forward_cam/image_raw/compressed`, `/sim/forward_cam/camera_info` | CompressedImage, CameraInfo | 10 Hz |
| `/sim/down_cam/image_raw/compressed`, `/sim/down_cam/camera_info` | CompressedImage, CameraInfo | 10 Hz |
| `/sim/ground_truth/pose` | geometry_msgs/PoseStamped (ENU) | 50 Hz |
| `/sim/ground_truth/twist` | geometry_msgs/TwistStamped (FLU) | 50 Hz |
| `/sim/ground_truth/gps` | sensor_msgs/NavSatFix | 50 Hz |

Unity subscribes to `/simulation/reset` (std_msgs/Bool). Topic names are on the `ROSSettings`
component; rates and JPEG settings are on each publisher and on `SimSettings`.

## Keys (Game view focused)

- `R` resets the vehicle to its start pose.
- `M` toggles keyboard flying without PX4: Shift/Ctrl collective, W/S pitch, A/D roll, Q/E yaw,
  Up/Down pusher, Space cuts all motors.
- Right drag orbits the chase camera, scroll zooms.

## Troubleshooting

- **PX4 stops after `selected parameter backup file` and never connects.** A PX4 startup
  command hung on its local socket, or an old PX4 is still running. Kill it and start again:
  `pkill -9 -f px4_sitl_default/bin/px4; rm -f /tmp/px4_lock-0 /tmp/px4-sock-0`.
- **Unity's console says it can't listen on TCP 4560.** Another editor or simulator has the port.
- **PX4 logs `poll timeout`.** Unity isn't stepping: play mode is paused or stopped.
- **Unity's console says `lockstep paused`.** PX4 stopped sending controls for three steps; Unity
  steps on its own until PX4 answers again. Usually PX4 was killed without closing the socket.
- **QGC stays disconnected.** Check PX4 is actually running (above) and that nothing else holds
  UDP 14550.
