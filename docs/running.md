# Running the sim

Three processes: Unity, PX4 SITL, and whatever ROS 2 wants to listen. QGroundControl is optional.

## 1. Unity

Open the project in Unity 6.6 and load `Assets/_Project/Scenes/Flight.unity`. Press Play. The
overlay in the top left says `PX4 SITL: waiting on TCP 4560` until PX4 connects.

The scene is generated by `Assets/Editor/DroneSim/SceneBuilder.cs` (menu: Drone Sim > Build
Flight Scene). Edit the builder, not the scene, so the setup stays reviewable.

Headless compile and scene rebuild:

```bash
/Applications/Unity/Hub/Editor/6000.6.0f1/Unity.app/Contents/MacOS/Unity -batchmode -nographics -quit \
  -projectPath . -executeMethod DroneSim.Editor.SceneBuilder.Build -logFile build.log
```

Edit-mode tests (MAVLink encoding against pymavlink golden frames, frame conversions, geo math,
actuator scaling). Close the editor first; batchmode can't open a project that's already open.

```bash
/Applications/Unity/Hub/Editor/6000.6.0f1/Unity.app/Contents/MacOS/Unity -batchmode -nographics \
  -projectPath . -runTests -testPlatform EditMode -testResults results.xml -logFile test.log
```

In the editor: Window > General > Test Runner > EditMode.

## 2. PX4 SITL

PX4 connects to Unity as a TCP client on port 4560 and runs in lockstep with it.

Use the same PX4 release as the flight controller and drone-2027's `px4_msgs` (v1.17.0):

```bash
git clone --recursive -b v1.17.0 https://github.com/PX4/PX4-Autopilot.git
cd PX4-Autopilot
make px4_sitl                     # build only, launches nothing
PX4_SIM_MODEL=gazebo-classic_standard_vtol ./build/px4_sitl_default/bin/px4
```

PX4 has no `none_standard_vtol` airframe (the only `none_` one is `none_iris`). The
gazebo-classic standard_vtol airframe (autostart 1040) is the one we want. Its startup runs
`simulator_mavlink`, which dials TCP 4560. Gazebo itself is only started by
`make px4_sitl gazebo-classic_standard_vtol`, so running the binary directly skips it. Don't use
`gz_standard_vtol`, which talks to Gazebo Harmonic over its own transport instead of MAVLink.

If Unity runs on another machine, set `PX4_SIM_HOSTNAME=<unity host>` for PX4.

`PX4_HOME_LAT`, `PX4_HOME_LON` and `PX4_HOME_ALT` do nothing on the PX4 side here, because
PX4's home comes from the GPS that Unity sends. Set them in the environment Unity starts from
(or on `GeoOrigin` under `Managers`) to move the world. The default is the SUAS 2026 field.
The magnetic field on `GeoOrigin` doesn't follow; set it for the new site from NOAA's
magnetic field calculator, or PX4's EKF will complain about heading.

QGroundControl finds SITL automatically on UDP 14550. PX4 also starts the uXRCE-DDS client on
UDP 8888.

Unity blocks each physics step until PX4 answers. If PX4 stops answering for three steps, the
bridge stops waiting until the next controls arrive, and a dropped connection returns it to
`waiting on TCP 4560`.

## 3. ROS 2

The PX4 side of ROS 2. Use Micro-XRCE-DDS-Agent v2.4.2; v3.x doesn't work with PX4's client.

```bash
MicroXRCEAgent udp4 -p 8888
```

drone-2027's flight checks start the agent themselves with `--sitl`, so skip this when
running those.

The Unity side of ROS 2 (cameras, IMU, ground truth, /clock):

```bash
ros2 run ros_tcp_endpoint default_server_endpoint --ros-args -p ROS_IP:=0.0.0.0
```

Unity connects to the endpoint at 127.0.0.1:10000. Change the address on the `ROSConnection`
component under `Managers` if the endpoint runs elsewhere, for example in Docker.

## Running drone-2027's flight checks against Unity

drone-2027 (`feat/uxrce-dds-port`) talks to PX4 over uXRCE-DDS and doesn't care which
simulator is under PX4. Its `docs/sitl.md` says `make px4_sitl gz_x500`; with Unity, run the
PX4 commands above instead, then its checks unchanged:

```bash
ros2 run drone check_link --sitl
ros2 run drone check_telemetry --sitl --duration 10
ros2 run drone check_hover --sitl --api
```

- The checks fly in multicopter mode only. They never command a transition, so a quadplane
  runs them as a quad.
- `check_goto_gps` and `check_gps_movement` take coordinates near Zurich in their examples,
  and `check_lap` uses Montreal. Move Unity's origin to match (`PX4_HOME_LAT` etc. above) or
  pass coordinates near the Unity origin, or the vehicle will try to fly across an ocean.
- On a Mac, run PX4 SITL and Unity natively and the ROS 2 side in drone-2027's
  `docker/Dockerfile`, with UDP 8888 published.

## Keys

- `R` resets the vehicle to its start pose.
- `M` toggles manual keyboard flying, for when PX4 is not running. Shift/Ctrl collective, W/S pitch,
  A/D roll, Q/E yaw, Up/Down pusher, Space cuts. A small attitude hold keeps hover level.
- Right drag orbits the chase camera, scroll zooms.

The sim runs without ROS. The publishers retry the endpoint and log one error; nothing else
depends on it.

## Topics from Unity

| Topic | Type | Rate |
|---|---|---|
| /clock | rosgraph_msgs/Clock | 10 Hz |
| /sim/imu/data | sensor_msgs/Imu | 10 Hz default, set on the publisher |
| /sim/forward_cam/image_raw/compressed, /sim/forward_cam/camera_info | CompressedImage, CameraInfo | 10 Hz |
| /sim/down_cam/image_raw/compressed, /sim/down_cam/camera_info | CompressedImage, CameraInfo | 10 Hz |
| /sim/ground_truth/pose | geometry_msgs/PoseStamped | 50 Hz |
| /sim/ground_truth/twist | geometry_msgs/TwistStamped | 50 Hz |
| /sim/ground_truth/gps | sensor_msgs/NavSatFix | 50 Hz |

Subscribed: /simulation/reset (std_msgs/Bool).

## PX4 channel mapping on the placeholder vehicle

Taken from PX4's `1040_gazebo-classic_standard_vtol` airframe (`PWM_MAIN_FUNC1..8`). The same
table is in code as `StandardVtolChannels`, and a test pins it.

| Channel | Actuator | PX4 range | Notes |
|---|---|---|---|
| 0 | Lift rotor front-right | 0..1 | CCW (`CA_ROTOR0_KM` > 0) |
| 1 | Lift rotor rear-left | 0..1 | CCW |
| 2 | Lift rotor front-left | 0..1 | CW |
| 3 | Lift rotor rear-right | 0..1 | CW |
| 4 | Pusher | 0..1 | |
| 5 | Left aileron | -1..1 | positive rolls left (`CA_SV_CS0_TRQ_R` = -0.5) |
| 6 | Right aileron | -1..1 | positive rolls right (`CA_SV_CS1_TRQ_R` = +0.5) |
| 7 | Elevator | -1..1 | positive pitches nose up |

The airframe has no rudder. PX4's `pwm_out_sim` sends motors as 0..1 and servos as -1..1.

When the real airframe gets its own PX4 config, update `StandardVtolChannels` and this table
together.
